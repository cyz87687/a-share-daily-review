## 原始需求复述

> "根据以上提示词，开发一套每天自动复盘的工具，最终生成可以每天更新的 html 文件"

## 已确认决策（不可推翻）

| # | 决策项 | 结论 |
|---|---|---|
| D1 | 数据源 | **mootdx 本地通达信数据**（全市场日线 + 板块），免费无 key，离线批量粗筛 |
| D2 | AI 复盘环节 | **双模式**：`prepare` 生成候选数据包 + 提示词供人工粘贴；配 API key 后 `auto` 全自动跑通 |

## 一、产品目标

**价值主张**：把收盘后 2–3 小时的复盘压缩为「一键跑批 + 15 分钟人工终审」，且每条判断都带数据溯源、依据强度与证伪条件，可跨日累积验证并反哺参数校准。

| # | 目标 | 可衡量指标 |
|---|---|---|
| G1 | **跑批时效** | 本地数据 → 发布 HTML 端到端 ≤ 10 分钟（auto 模式，M=60）；人工终审 ≤ 20 分钟 |
| G2 | **零幻觉** | HTML 中 100% 数字可溯源至原始字段或显式计算式；缺失字段一律渲染 `N/A`，全站 0 处推算/编造值。由「质量门自动校验」在发布前拦截 |
| G3 | **闭环完整** | 非首日运行 100% 输出昨日对账表（兑现/证伪/未触发三态）；周度可输出按判定类型（资金定性/板块定位/介入信号）分类的证伪率 |

## 三、需求池

### P0 — 首版必须（Must have）

#### 数据层

| ID | 需求 | 验收标准 |
|---|---|---|
| **P0-1** | **mootdx 数据接入** | 通过 `mootdx` 读取本地通达信数据目录（路径可配），一次性载入全市场日线（OHLCV + 成交额 + 换手率）+ 板块成分；单日全市场载入 ≤ 60s；数据目录不存在/日期无数据时**报错退出**，禁止用旧数据静默顶替 |
| **P0-2** | **候选池构建** | 按当日成交额降序取 Top **N**（默认 500）为候选池；北交所标的默认排除（参数 `exclude_bj=true`）；输出候选池规模与成交额分位阈值到运行日志 |
| **P0-3** | **排除清单硬剔除** | 实现 5 类剔除的可执行子集：① ST/*ST/退市（名称匹配）② 上市未满 **D** 个交易日（按本地首根日线计）③ 当日一字板（open=high=low=close，或最高=最低）④ 停牌/无成交（当日成交额=0 或缺失）⑤ 成交额 < 1亿 且 流通市值 < 50亿。每条剔除记录**剔除原因**到 `exclude_log` |
| **P0-4** | **四维异动筛选 + 触发标签** | 实现量能（放量 / 极致缩量）、价格（|涨跌幅| > **P_TH**）、形态（突破/跌破 MA5/10/20、大阳/大阴、长影线）、板块（强势板块 Top **K** 成分且个股涨幅 ≥ 1.5%）四类标签；额外实现【炸板】标记（最高价触及涨停价 且 收盘价 < 涨停价，单独标记不剔除）。每只留存标的 `tags` 数组非空且每标签可回溯到触发时的原始数值 |
| **P0-5** | **优先级排序与截断** | 优先级 = 触发维度数（≥3 高 / 2 中 / 1 低）；同级内按 \|涨跌幅\| × 量比 降序；留存 **M** 只（默认 60）；被截断标的进入 `truncate_log`（含截断原因 + 名录 + 其量价强度分），在 HTML 中可展开查看 |
| **P0-6** | **留存日志落库** | 按提示词定义的字段落库为 `data/logs/holdings-{date}.csv`：`代码\|名称\|触发标签\|优先级\|所属板块及涨幅排名\|量比\|收盘价\|次日开盘表现\|次日收盘表现`；次日开盘/收盘列由次日运行回填；**文件按日幂等**（重跑同日覆盖，不重复追加） |

#### AI 层

| ID | 需求 | 验收标准 |
|---|---|---|
| **P0-7** | **候选数据包生成** | 为每只留存标的导出 AI 复盘所需的**全部原始字段**（不导出结论性字段）：行情 20 日 OHLCV 摘要、量比、5/10/20 日均量、涨跌幅、换手率、流通市值、所属板块及板块当日涨幅与排名、涨停价/跌停价、是否炸板、昨日留存日志中该股的历史判断。缺失字段显式写 `N/A` 并附缺失原因 |
| **P0-8** | **提示词装配** | 将上游 prompt 文档（角色与边界 / 数据口径声明 / 单股 8 项 / 市场总结 6 项 / 禁止清单 / 质量门 / 输出 Schema / 参数表）作为参数注入模板（N/D/Q_UP/Q_LOW/P_TH/K/M 与当日日期），与数据包拼装为 `output/{date}/prompt.txt`。`prepare` 模式在此停止并打印人工操作指引 |
| **P0-9** | **auto 模式 LLM 调用** | 配置 API key 后自动调用；按 **每批 5 只** 分批请求（避免单次输出过长导致截断），市场总结单独一批；失败按指数退避重试 ≤ 3 次，仍失败则该批次在 HTML 中标记为「AI 生成失败·待人工补充」，**不中断整轮** |
| **P0-10** | **AI 输出解析与结构化** | 解析 JSON（允许 ```json 围栏与轻微格式容错），失败时降级为「原文保留 + 标记未结构化」，不丢内容；结果落库 `data/reviews/{date}.json`，schema 与上游文档第八节一致 |
| **P0-11** | **质量门自动校验（防幻觉硬闸门）** | 发布前逐项检查上游文档第六节 6 条：① 数值溯源（HTML 中出现的每个价位/涨幅/量比必须能在数据包中匹配到，或为合法 `N/A`）② 每只有证伪条件且非空 ③ 非首日昨日对账已执行 ④ 机会均为「触发+放弃」形式（正则检测裸预测词：有望/应该会/谨慎乐观/我觉得）⑤ 留存日志已更新 ⑥ 输出含数据截止日期。任一不通过 → 命令行报错 + HTML 顶部挂红色警示条，但**仍发布**（不静默通过） |
| **P0-12** | **昨日对账闭环** | 非首日运行时读取昨日志，按代码匹配今日行情，自动判定三态（**兑现 / 证伪 / 未触发**）并生成对账表 `代码\|昨日预案\|今日兑现/证伪\|修正结论`；「修正结论」列在 `prepare` 模式留空待人工填，`auto` 模式由 AI 生成 |

| **P0-17** | **人工终审交互（前端）** | 页面内置终审面板：每只卡片可「剔除误判」/「加入观察池」（上限 5，超出提示）；顶部汇总已选数量；点击「导出终审结果」下载 `review-{date}.json`（localStorage 持久化，刷新不丢） |
| **P0-18** | **终审回填与重渲染** | CLI `finalize --date {date} --review {json}` 读取终审结果，写回 `holdings-{date}.csv`（标记人工剔除/观察池）并生成明日对账基线，同时重新渲染当日 HTML（终审状态可视化 + 剔除卡片折叠） |

## 四、UI 设计稿

### 4.1 配色与信息层级约定（强制）

```
涨 / 红   主色 #E1251B   浅底 #FFF1F0   用于：上涨、放量、兑现、主线
跌 / 绿   主色 #17A673   浅底 #E8F8F2   用于：下跌、缩量、证伪、弱势
平 / 灰   #8C8C8C                       用于：平盘、未触发、N/A
警示      #FA8C16                       用于：证伪条件、赔率不足、质量门告警
中性文字  #1F2329 / #646A73             用于：正文 / 次要说明
页面底色  #FFFFFF  卡片 #FAFAFA  分割线 #E5E6EB
```

信息层级：**数字 > 标签 > 依据 > 结论**。任何结论性文本（资金定性、板块定位）必须与「依据 + 强度」同屏呈现，不得单独出现。

### 4.4 关键交互说明

| 交互 | 行为 |
|---|---|
| 溯源展开 | 点击 ⓘ 展开该股全部展示数值的「字段 = 原值 → 计算式 → 结果」，`N/A` 显示缺失原因 |
| 剔除/观察池 | 纯前端 localStorage 持久化，观察池上限 5；顶部实时汇总，导出 JSON |
| 筛选与分组 | 纯前端 JS，不刷新；URL hash 记录筛选状态便于分享 |
| 折叠区 | 日志/配置默认折叠，避免长页面，但均可一键导出 |
| 无 JS 降级 | 关闭 JS 时全部内容仍静态可读（终审交互除外） |
